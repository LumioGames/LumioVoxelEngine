# 0012 · Canonical 解码按输入长度线性收费，长度上限与拒绝命名都不落本库

- 日期:2026-08-29
- 状态:生效

## 背景

[0011](0011-voxel-local-canonical-object-encoding.md) 落地后的独立深审报出四条待决问题,都不在该 ADR 的决策面上,但都需要一个明确落点。

`Parser::string()` 的普通字符分支每读一个字符就 `str::from_utf8(&bytes[at..])` 校验**整个剩余缓冲区**,于是字符串开销与其后字节数成正比,整体二次。实测(release,manifest 形状,N 个 `chunkRevision.c:i:0:0` 成员):

| chunks | manifest 字节 | 修复前 | 修复后 |
|---:|---:|---:|---:|
| 1,000 | 27.6 KB | 6,057 µs | 360 µs |
| 4,000 | 112.5 KB | 89,991 µs | 1,617 µs |
| 16,000 | 458.2 KB | 1,563,167 µs | 7,394 µs |

审查方将其定为 P2,理由是查不到 restore 字节的信任边界。该边界成立:`RestorePreflight::validate` 接受任意 `&[u8]` 且不校验长度,而 VOX-D-008 已裁 Host 拥有 DAG 编排、fsync 与 Active 指针切换——snapshot 由 Host 落盘,restore 时从文件系统读回,**字节来源是文件而非内存中的可信对象**。损坏、截断或被篡改的存档都走这条路径,故按跨信任边界处理。

其余三条:孤代理转义的实际返回值是通用 `DecodeError::Malformed`,而 0011 与提交信息都称其为「具名错误」;单射性只有 17 个手挑用例;形态成员只在 `canonical_fingerprint` 一面。

## 决策

- **解码开销按输入长度线性收费**:UTF-8 在 `parse()` 入口一次性校验,解析器持 `&str`,字符分支退化为一次边界检查。拒绝集合不变——`decode` 把解析结果重新编码后与原字节逐字节比较,而重新编码的产物是 Rust `String`,故凡被接受者本就是合法 UTF-8,两种写法的判决完全相同,变的只有开销。
- **不在本库给 `validate` 加字节长度上限**,上限归调用方(Host):
  - 编码侧的字节预算本就是调用方给的(`MemoryCaptureWriter::new(cap)`),不是库常量;解码侧立一个常量会成为整个 codec 上唯一的硬编码字节数。
  - 该常量无从取值:manifest 每 chunk 一个成员,而本 crate 不决定一个世界有多少 chunk,定死上限等于悄悄给世界规模封顶。
  - 拿到 `&[u8]` 时字节已在 Host 内存里,此处再拒等于在开销发生**之后**才拒,防不住它本该防的东西。
  - 去掉超线性项后剩下的是「解析调用方已经物化的字节」这一正常线性开销。
- **孤代理与成对代理转义继续以通用 `Malformed` 拒绝,不新增具名变体**;0011 的措辞按实现改正。跨端错误标识取自生成的封闭表 `STABLE_ERROR_IDS`,其中没有对应 id,新增 Rust 侧变体带来的区分会**止步于端口边界**,C# Runtime 观察不到;要真正具名须先在 `LumioGameEngineArchitecture` 改契约。行为本身(全形式拒绝)是 0011 的决策,不变。
- **单射性改由左逆属性扫描机器证明,不引入 fuzz 基建**:`decode(encode(x)) == x` 在约 29,400 例语料上逐例断言(左逆蕴含单射),另以 `HashMap<Vec<u8>, _>` 正向撞库,捕捉编解码「互相抵消地错」这一左逆单独漏掉的情形。语料按结构字节、伪造分隔、转义字面量、C0 / DEL / astral / 超长名值构造。
- **snapshot manifest 字节由摘要钉住**:0011 声称「改动前写出的 snapshot 改动后仍可 restore」,此前无任何测试守这条。期望值仍按 0011 出自 `canonical_encoding_oracle.py`,不由被测代码自产。

## 后果

- 解码比 0011 之前的 `decode_canonical_pairs` 慢约 2.5 倍(16k chunk:7,394 µs vs 2,941 µs)——代价来自类型化值、转义与规范性回编码,是 0011 的既定成本,且现在同为线性。
- 复杂度回归只能由开销判据守住:修复前后接受与拒绝的字节集合完全相同,任何语义断言都分不开两者。故留了一条比值型判据(输入 ×8 时耗时不得 ×16 以上),它不编码机器速度,但确实是计时测试。
- **残留 gap(显式点名,非遗漏)**:形态成员 `canonicalForm` 只出现在 `canonical_fingerprint` 一面,snapshot manifest / receipt / restore shadow / query plan 四面都没有,故这四面的字节不自我识别格式。这是为保住字节兼容的有意取舍(0011「四个面的字节不变」正建立在此),TD 已裁决维持。要消掉它须接受这四面的摘要断代。
